# Canvas worker numeric configuration oracle

`contracts/canvas-worker-numeric-lexical-oracle.json` adds 64 lexical observations
to the unchanged 15-case configuration baseline and its 18 malformed combinations.
It was generated by executing the real configuration factory in the exact
published issuance 0.1.72 image, Python 3.12.13. The image's worker source bytes
matched published Git source `85b128a85426b3f5aeaf6f948ba5dfa2836e95d8`; the fixture
records both source/image identity and the original baseline's revision/hash.
No runtime implementation, baseline fixture, dependency or crypto pin changes.

All fields are language-neutral JSON. Integer **outputs** are canonical base-10
strings, not JSON numbers, so values beyond u64 remain exact in Rust, JavaScript
and other consumers. Inputs are original environment strings, including Unicode
and separators. Expected successful output includes every legacy configuration
field; failures explicitly occur during configuration with category `invalid_number`
and legacy exception `ValueError`. Do not round, truncate, skip or relabel cases.
Unicode inputs use JSON escapes to preserve their exact decoded code points
across tools with different default text encodings.

The observed behavior includes:

- Unicode decimal digits (including mixed scripts) and valid digit separators.
- Rejection of misplaced separators, non-decimal numeric characters, BOM and
  zero-width/control-prefix/suffix forms.
- Float exponent/separator grammar, infinity/NaN bounds and underflow behavior.
- Integers above signed 64-bit and u64 accepted at startup; the selected runtime's
  4300-decimal-digit conversion limit, versus float overflow clamping high.

The standard-library unittest test is also pytest-discoverable and executes all
64 vectors against `issuance.canvas_worker.CanvasSyncWorkerConfig.from_env` with
an isolated environment. It checks the interpreter's integer conversion limit
instead of silently skipping a runtime-policy mismatch. It can run in the pinned
published image with this repository mounted read-only, no network or services:

```sh
python -m unittest discover -s /verification/tests/unit \
  -p test_canvas_worker_numeric_oracle.py -v
```

## Rust cutover boundary

These are configuration observations, not database or whole-worker acceptance.
The current Rust configuration rejects non-finite floats and large integers and
trims explicit worker identities; do not call its existing bounded tests parity
proof. Widening only from `i64` to `usize` is insufficient for this corpus. Preserve
downstream scheduling, SQL/time range, error-phase and loop-survival behavior in
addition to numeric grammar, through one authoritative shared Rust implementation.

Extend the Rust consumer with this exact fixture after maintainer/protected merge
and complete downstream range/error-cycle tests. Keep the original configuration
and result-oracle fixtures, Python worker, processors, webhooks and production
consumers until whole-worker/all-consumer, routing, readiness and beta gates pass.
This test-only change grants no activation, deletion, publication or deployment
authorization and does not alter the independent beta 1.1.217 release candidate.
